서버는 건물이고, InfiniBand 는 건물끼리 잇는 전용 터널입니다. GPU 여러 대가 함께 학습할 때 서버끼리 주고받는 데이터를 일반 도로 대신 이 터널로 빠르게 보냅니다.

InfiniBand 가 뭘까요?

서버 사이에 판 전용 터널입니다

GPU 여러 대가 한 모델을 함께 학습하면 계산 결과를 계속 주고받습니다. 같은 건물 안에서는 복도로 금방 만나지만, 다른 건물과는 일반 도로를 건너야 해서 금방 막힙니다. 그래서 건물 사이에 전용 터널을 따로 팝니다.

조금 더 자세히

InfiniBand(IB)는 서버 사이 고속 데이터 전송을 위한 전용 네트워크입니다. 카드, 케이블, 스위치를 합친 망 전체를 fabric 이라고 부릅니다. 서버 안 GPU 끼리는 NVLink 로, 서버 사이는 이 망으로 통신합니다.

RDMA 는 네트워크 카드가 상대 서버의 메모리에 직접 쓰는 방식입니다. CPU 와 운영체제가 중간에서 하는 일이 줄어 지연이 짧습니다. NCCL, Mooncake, UCX 같은 분산 학습·추론 도구가 이 방식을 씁니다. IB 위에서 IP 로 통신하는 IPoIB 는 보조 기능이지만, 고객이 이번 기능에서 꼭 원한 것 중 하나입니다.

예전 방식은 카드가 몇 장이든 노드마다 ten1010.io/rdma 리소스가 1개였습니다. 그래서 노드당 IB Workspace 가 하나로 묶였고, 여러 Pod 가 같은 카드를 나눠 쓸 때 각자 몫이 정해지지 않았고, 다른 프로젝트 Pod 와도 통신할 수 있었습니다.

터널 입구는 어떻게 생겼을까요?

진짜 문은 PF, 나눈 작은 문은 VF입니다

건물 벽에 뚫린 진짜 터널 문이 PF 입니다. SR-IOV 는 그 문에 칸막이를 세워 작은 문(VF) 여러 개로 나눕니다. 문은 늘어나도 터널 폭은 그대로라서, 작은 문끼리 폭을 나눠 씁니다.

값 바꿔 보기

큰 문 하나를 작은 문 몇 개로 나눌까요?

작은 문(VF) 개수

200 Gb/s 는 개발 클러스터 카드 속도를 빌렸고, 나눈 값은 단순 계산한 예시입니다. 실제 VF 수는 카드 펌웨어 값이 정하고 화면에서는 바꾸지 않습니다.

조금 더 자세히

PF(Physical Function)는 IB 카드의 실제 포트입니다. 카드 한 장에 1~2개 있고, 서버 한 대에 카드가 여러 장 꽂히기도 합니다(SDI 서버는 포트가 12개까지 있습니다). 이름은 mlx5_0, ibp193s0f0 같은 모양입니다.

VF(Virtual Function)는 PF 를 소프트웨어로 나눈 가상 PCI 장치입니다. Pod 안에서는 진짜 장치처럼 보이고 mlx5_12 같은 이름이 붙습니다. 번호는 미리 알기 어렵습니다. PF 하나에서 나오는 VF 수는 카드 펌웨어 값(NUM_OF_VFS)이 정하고, 펌웨어에서 SR-IOV 가 꺼져 있으면 그 PF 는 Blocked 가 됩니다.

문은 어떻게 빌려줄까요?

통째로 빌려주거나, 하나씩 나눠 줍니다

PF 모드는 큰 문을 팀에 통째로 빌려주고, 팀원 여럿이 문 앞 자리(슬롯)를 나눠 앉습니다. SR-IOV 모드는 작은 문 하나를 작업자 한 명에게 줍니다. 설치하는 사람이 처음에 하나를 고르면 클러스터 전체가 그 방법을 씁니다.

다른 팀과 섞이지 않을까요?

관제탑이 팀마다 출입증을 줍니다

터널에 들어가려면 관제탑이 준 번호표가 있어야 합니다. 관제탑은 팀마다 출입증 색을 정해 두고, 색이 같은 문끼리만 이야기하게 합니다. 그래서 A팀 작업자는 B팀 작업자에게 터널로 말을 걸 수 없습니다.

값 바꿔 보기

어느 문과 어느 문이 터널로 이야기할 수 있을까요?

조금 더 자세히

Subnet Manager(SM) 는 fabric 전체를 관리하는 프로그램입니다. 포트마다 주소(LID)를 주고 통신 권한(P-Key)을 적용합니다. SM 이 없으면 케이블이 꽂혀 있어도 새 장치가 통신을 시작하지 못합니다. AIPub 은 스위치 안의 SM 을 끄고, SM 노드 2대에서 opensm 을 대장(master)과 대기(standby)로 돌립니다. 스위치 SM 은 VF 를 알아보지 못하기 때문입니다.

P-Key 는 이더넷의 VLAN 과 비슷한 파티션 키입니다. 프로젝트마다 하나씩 나오고, 같은 P-Key 의 정식 멤버끼리만 통신합니다. 우리 VF 는 모두 기본 파티션(0x7fff)에서 제한 멤버로 내려가서, 다른 팀 VF 나 주인 없는 VF 와는 막힙니다. 다만 PF, SM, 다른 조직 장비처럼 정식 멤버인 장비와는 통신합니다.

SM 노드 2대가 모두 멈추면 이미 통신 중인 장치는 대부분 계속 통신합니다. 대신 새 Pod 의 장치가 올라오지 않고, 배정을 바꿔도 반영되지 않고, 케이블이나 장비에 문제가 생기면 복구되지 않습니다.

기본 설치(PF 모드, isolation: none)는 출입증을 쓰지 않고 고객사가 원래 쓰던 SM 을 그대로 씁니다. 우리 쪽에서 SM 상태를 알 수 없어서 SM 경고도 띄우지 않습니다. 개발 클러스터가 이 경우입니다.

누가 무엇을 정할까요?

관리자는 개수만, 어느 문인지는 시스템이 정합니다

인프라 담당자가 방법을 고르고, 관리자는 팀마다 건물별 문 개수만 적습니다. 프로젝트 매니저는 배정 현황을 봅니다. 어느 문을 줄지는 시스템(operator 프로그램)이 자동으로 고르고, 팀원은 작업자 한 명에게 문이 몇 개 필요한지만 말합니다.

조금 더 자세히
  • 노드를 프로젝트에 붙이면 그 노드의 문은 0개로 시작합니다. Admin 이 InfiniBand 설정에서 개수를 정해야 그 노드에서 쓸 수 있습니다.
  • 저장한 개수는 시스템이 바꾸지 않습니다. 0개로 저장할 수도 있습니다.
  • 서버(웹훅)는 네 경우에 저장을 거부하고, 화면은 서버 메시지를 그대로 토스트로 보여 줍니다. 남은 개수보다 많이 요청할 때, Blocked 노드의 개수를 늘릴 때, 노드들이 서로 다른 fabric 일 때, IP 대역의 주소가 모자랄 때입니다.
  • 개수를 늘리면 시스템은 반납 중인 자기 문부터 되살리고, 모자라면 빈 문을 줍니다.

그 숫자는 어디에 적힐까요?

팀 계약서와 건물 장부에 적힙니다

Admin 은 팀 계약서에 "건물 1 에서 문 2개" 처럼 숫자만 적습니다. 시스템은 계약서를 보고 건물 장부에 어느 문이 그 팀 것인지 적습니다. 장부에는 다른 팀 정보도 함께 있어서 Admin 화면에서만 읽습니다.

조금 더 자세히

IBNetwork 는 프로젝트마다 하나씩 자동으로 생기고 이름이 프로젝트 이름과 같습니다(60자 이하 DNS-1123). Admin 이 고치는 칸은 spec.nodes[].numVfs 하나이고, 주소 대역은 spec.ipoib.cidr 입니다. 시스템이 채우는 status 에는 mode · isolation · pkey · resourceName 과 노드별 desired · current · active · allocated · pendingRelease 가 있습니다.

SriovNodeState 는 IB 노드마다 하나입니다. 노드에 ib-subnet 라벨과 ib-pf 어노테이션이 있으면 생깁니다. spec.vfs[] 에 문마다 주인(owner)과 반납 여부(releasing)를, status.vfs[] 에 장치 이름·상태(phase)·쓰는 Pod(allocatedTo)를 적습니다.

노드는 주인이 정해진 문을 ten1010.io/ib-<프로젝트> 리소스로 kubelet 에 광고합니다. 예전 ten1010.io/rdma 는 없어집니다. 옛 키로 만든 Workspace 를 편집하면 화면이 새 키로 바꿔 채우고, 저장하면 Workspace 가 한 번 다시 시작된다고 안내합니다.

작업자는 문을 어떻게 받을까요?

일곱 정거장을 지나 문이 붙습니다

팀원이 "작업자 한 명에 문 2개" 를 요청하면 일곱 정거장을 지나 문이 붙습니다. 팀원이 화면에서 직접 하는 일은 첫 정거장뿐이고, 나머지는 시스템이 처리합니다.

조금 더 자세히
  • ② 웹훅은 그 프로젝트에 연결되지 않은 Namespace 의 요청을 거부합니다. 다른 프로젝트 문을 요청하지 못하게 막는 유일한 지점입니다.
  • ③ 웹훅이 네트워크 어노테이션을 요청 수만큼 붙이고 IPC_LOCK 권한과 NCCL_IB_PKEY=1 을 넣습니다. 그래서 화면은 이 값을 받지 않습니다.
  • Pod 하나는 노드 한 곳에만 뜹니다. 그래서 화면의 가용·최대는 노드 합계가 아니라 노드별 값 중 가장 큰 값입니다. InfiniBand 에는 Quota 를 적용하지 않고, 회수 대기 문은 Free 에 넣지 않습니다.
  • InfiniBand 입력은 Workspace 생성·편집과 Workspace 템플릿에만 있습니다. Operation, Job, CronJob, ChainJob, File server 는 지원하지 않습니다.

터널 안에도 주소가 있을까요?

문마다 터널 주소가 하나씩 붙습니다

모든 작업실에는 일반 도로 주소(Pod IP)가 하나 있습니다. 터널 문을 받으면 문마다 터널 주소(IPoIB IP)가 하나씩 더 붙습니다. 팀 계약서에 주소 대역이 적혀 있을 때만 붙고, 기본 설치에는 대역이 없습니다.

조금 더 자세히

주소 대역은 IBNetwork 의 spec.ipoib.cidr 입니다. 자동으로 생기는 IBNetwork 는 설치 값 defaultIpoibCidr(기본 빈 값)를 받고, 한 번 정하면 바꿀 수 없습니다. 주소가 모자라면 배정 저장이 422 로, Pod 생성이 403 으로 거부되고 화면은 서버 메시지를 그대로 보여 줍니다.

PF 모드에서도 IP 는 자리(슬롯)마다 하나씩 붙습니다. 같은 PF 의 자리를 여러 개 받으면 장치 이름은 반복되고 IP 만 다릅니다. 화면은 Pod 어노테이션 aipub.ten1010.io/ib-interfaces 를 읽어 한 항목을 한 줄로 그리고, net1 같은 인터페이스 이름은 보여 주지 않습니다.

그림의 주소들은 BE 답변에 적힌 예시 값입니다.

개수를 줄이면 바로 빠질까요?

쓰던 문은 작업자가 나갈 때까지 기다립니다

Admin 이 문 개수를 줄여도 문은 바로 다른 팀에 넘어가지 않고 반납 중이 됩니다. 아무도 안 쓰던 문은 30초쯤 뒤에, 쓰던 문은 작업자가 나갈 때까지 기다렸다가 빈 문이 됩니다. 노드를 프로젝트에서 빼도 똑같이 반납합니다.

조금 더 자세히
  • 반납할 장치에 releasing: true 가 붙습니다. 시스템은 안 쓰는 장치부터, 같으면 뒤쪽 장치부터 고릅니다. 주인은 회수가 끝날 때까지 그 프로젝트입니다.
  • 반납 중에 개수를 다시 늘리면 반납 중인 자기 문부터 되살립니다.
  • PF 모드는 PF 를 통째로 반납하므로, 그 PF 를 나눠 쓰는 Pod 가 모두 끝나야 풀립니다.
  • 줄인 숫자는 저장 즉시 다른 프로젝트의 "최대" 에 더해집니다. 장치는 회수가 끝나야 실제로 넘어가고, 그 사이 다른 프로젝트 배정은 회수가 끝난 뒤 채워집니다.
  • 노드를 빼는 확인창은 노드의 isolation-mode 에 따라 안내가 다릅니다. lenient 는 "Pod가 종료될 때까지 InfiniBand가 회수되지 않습니다", strict 는 "사용 중인 Pod를 내보낸 뒤 InfiniBand를 회수합니다" 입니다.

문이 고장 나면 어떻게 알까요?

문마다 표시등이 있습니다

문마다 상태 표시등이 있습니다. 새 문은 Pending 으로 시작해 2분 안에 번호표와 출입증을 받으면 Active 가 되고, 못 받으면 Down 이 됩니다. 큰 문이 잠기면(Blocked) 그 안의 작은 문도 함께 못 씁니다.

조금 더 자세히
배지실제 뜻데이터 phase
Active통신 가능. VF 는 LID 등록과 P-Key 적용까지 끝남Ready
Pending준비 중. 장치는 120초까지 기다림Pending
Down링크·SM·P-Key 를 확인해야 함Degraded
BlockedPF 없음, 펌웨어에서 SR-IOV 꺼짐, VF 풀 생성 실패 등Blocked
ErrorVF 없음, 다른 드라이버, 설정 실패 (SR-IOV 모드만)Missing · ForeignDriver · SyncFailed
Unknown배정에서 빠졌지만 Pod 가 쓰는 중이거나 아직 보고 전Unknown

판정은 PF 다음에 장치 순서로 합니다. PF 가 막히면 그 아래 장치는 따로 판정하지 않고 PF 의 사유를 그대로 받아 Blocked 가 됩니다. 화면은 분기를 reason 으로 하고, message 는 원문 그대로 보여 줍니다.

노드 전체에 영향이 있으면 탭 맨 위에 배너를 띄우고, 여럿이면 Blocked, SM 없음, Degraded 순서로 위에서부터 쌓습니다. SR-IOV 모드에서 SM 만 돌리는 노드는 SR-IOV 가 꺼져 있는 것이 정상이라 회색 안내("이 노드는 Subnet Manager 전용으로 구성되어 VF를 만들지 않습니다.")로 보여 줍니다. PF 카드의 Unhealthy n 배지는 그 PF 아래 Down · Error 인 VF 만 셉니다.

예전 ten1010.io/rdma 방식과 무엇이 달라졌나요?

예전에는 카드가 몇 장이든 노드마다 리소스가 1개라서 노드당 IB Workspace 가 하나로 묶였고, 다른 프로젝트 Pod 와도 통신할 수 있었습니다. 이제는 Admin 이 프로젝트마다 노드별 개수를 정하고, 리소스 이름도 ten1010.io/ib-<프로젝트> 로 프로젝트마다 따로 생깁니다.

1 왜 터널을 파나 · 6 계약서와 장부

Pod 가 mlx5_0 을 네 번 받았어요. 고장인가요?

고장이 아닙니다. PF 모드는 큰 문 하나를 자리 8개로 광고합니다. 노드에 큰 문이 하나뿐이면 같은 문의 자리를 여러 개 받아 장치 이름이 반복됩니다. 개발 클러스터의 test-ws 가 이 경우입니다.

3 문을 빌려주는 방법

VF 를 많이 나누면 더 빨라지나요?

빨라지지 않습니다. 문만 늘고 터널 폭은 그대로라서, 여러 VF 가 동시에 많이 보내면 PF 의 대역폭을 나눠 씁니다.

2 큰 문과 작은 문

다른 프로젝트 Pod 와 InfiniBand 로 통신할 수 있나요?

출입증(P-Key)을 켠 설치에서는 막힙니다. 다른 팀 VF 와는 함께 속한 파티션이 기본 파티션뿐이고, 거기서 둘 다 제한 멤버이기 때문입니다. 다만 PF·SM·다른 조직 장비처럼 정식 멤버인 장비와는 통신합니다. 출입증을 끈 기본 설치(개발 클러스터)는 격리가 없습니다.

4 관제탑과 출입증

관제탑(SM)이 모두 멈추면 학습이 끊기나요?

이미 통신 중인 장치는 대부분 계속 통신합니다. 그 사이 새 Pod 의 장치가 올라오지 않고, 배정 변경도 반영되지 않습니다. 그래서 화면은 오류가 아니라 경고로 알리고, 프로젝트 상세의 InfiniBand 설정 버튼을 잠급니다.

4 관제탑과 출입증

노드를 붙였는데 Workspace 생성에 InfiniBand 줄이 안 보여요.

노드를 붙이면 문은 0개로 시작합니다. Admin 이 프로젝트 상세의 InfiniBand 설정에서 그 노드의 개수를 정해야 합니다. 또 InfiniBand 줄은 "GPU 사용" 탭에서 GPU 를 고르고, 그 GPU 가 있는 노드 중 하나라도 이 프로젝트 배정이 1개 이상일 때만 보입니다.

5 누가 무엇을 정하나 · 7 문을 받기까지

배치 가이드에 용량 초과가 떠요.

요청한 개수가 그 노드의 이 프로젝트 몫(Total)보다 많다는 뜻입니다. 이 프로젝트 배정이 아예 없는 노드도 스위치를 켜면 용량 초과로 보입니다. 기다려도 들어가지 않으니 Admin 에게 배정을 늘려 달라고 하거나 요청을 줄입니다. 지금 비어 있는 수(Free)보다만 많으면 여유 부족입니다.

7 문을 받기까지

Workspace 상세에 IPoIB IP 열이 없어요.

프로젝트에 터널 주소 대역(spec.ipoib.cidr)이 없어서입니다. 기본 설치는 대역이 비어 있고, 한 Workspace 의 장치 중 IP 가 하나라도 있을 때만 열이 나옵니다.

8 터널 주소

Pod 가 VF 2개를 받으면 IP 는 모두 몇 개인가요?

대역이 있으면 3개입니다. 도로 주소(Pod IP) 1개에 문마다 터널 주소(IPoIB IP)가 1개씩 붙습니다.

8 터널 주소

개수를 줄였는데 다른 팀이 그 문을 바로 못 써요.

줄인 문은 회수 대기가 되고, 주인은 회수가 끝날 때까지 원래 프로젝트입니다. 안 쓰던 문은 30초쯤 뒤에, 쓰던 문은 Pod 가 끝난 뒤에 미할당이 되고 그때 다른 팀으로 넘어갑니다.

9 문 반납

팀원에게는 노드 상세의 InfiniBand 탭이 왜 안 보이나요?

노드 장부 한 권에 그 노드를 쓰는 모든 프로젝트의 Pod 이름과 네트워크 이름이 들어 있어서, 노드 상세 InfiniBand 탭은 Admin 에게만 보입니다. 팀원은 Workspace 상세에서 자기 Pod 가 받은 장치만 봅니다.

6 계약서와 장부 · 8 터널 주소

PF 카드가 Blocked 면 그 안의 VF 는요?

모두 쓸 수 없습니다. PF 가 막히면 그 아래 VF 는 PF 의 사유를 그대로 받아 Blocked 가 되고, 집계(VF 수 · Assigned)에서도 빠집니다.
