# Explain Concept - AIPub Two-Layer Explainer

주제: $ARGUMENTS

HTML 한 장을 쓴다. 1층은 익스플로러블 익스플레이너(값을 바꿔 보는 개념 글), 2층은 인터랙티브 데모(저절로 재생하고 직접 눌러 보는 제품 화면)다. 완성 예시는 [`examples/infiniband.html`](examples/infiniband.html) 이다. **쓰기 전에 이 예시를 열어 모양을 그대로 따른다.**

```
${CLAUDE_SKILL_DIR}/
  runtime/explainer.css   ← 토큰(라이트·다크·AIPub 화면색)·그림·모달·장면 스타일. <style> 에 그대로 넣는다
  runtime/symbols.svg.html← 캐릭터(역할 다섯)·화살표 기호. <body> 맨 앞에 그대로 넣는다
  runtime/scenes.js       ← 데모 재생기·앱 틀·모달·목차·테마·값 바꿔 보기. 마지막 <script> 에 그대로 넣는다
  references/blocks.md    ← 1층 칸·2층 블록·장면 동작 문법
  examples/infiniband.html   ← 완성 예시. 사내 링크는 href="#" 로, 노드 이름은 예시 값으로 바꿔 두었다
```

실제 클러스터 값은 저장소에 올리지 않는다. 값을 대조할 표(`expected.md`)는 각자 작업 디렉터리의 `fixtures/<주제>/<클러스터>/` 에 둔다.

## 두 층

| 층               | 독자가 얻는 것                           | 칸 하나의 모양                                                                       |
| ---------------- | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| 1층 · 개념       | 이게 무엇이고 왜 있는지                  | 번호 → 캐릭터 질문 → 한 줄 답 → 일러스트 → 두세 문장 → 값 바꿔 보기 → 조금 더 자세히 |
| 2층 · AIPub 화면 | 그 개념을 제품 어디서 누가 어떻게 쓰는지 | 모달: 하는 일·누가·어디서·Figma → 앱 틀 데모 → 값 바꿔 보기 → 연결 카드 3장          |

- 2층은 칸마다 "AIPub 화면에서 보기" 버튼으로 여는 큰 모달이다. 따로 된 페이지나 전체 펼치기 전환은 만들지 않는다.
- **비유는 하나만 정해 끝까지 쓴다**(IB: 서버=건물, IB=전용 터널). 맨 위 lead 에 비유를 밝히고, 아래쪽에 용어 짝꿍표 · Q&A · 출처 · 고친 기록을 두고, 용어 짝꿍표에 비유 ↔ 실제 이름 ↔ AIPub 화면을 둔다.
- 칸 순서는 개념이 쌓이는 순서다: 왜 → 구성 요소 → 방식 → 누가 무엇을 정하나 → 데이터 → 전체 흐름 → 예외(반납·상태) → 실제로 볼 곳 → 용어.

## 재료 찾기 (읽은 것만 쓴다)

1. **정책서**(Confluence): 화면·숫자·문구. 하위 페이지까지 펼쳐 읽는다.
2. **Figma**: 화면 모양과 실제 문구. 노드 링크를 2층 카드에 단다.
3. **쿠버네티스 리소스**(Polaris, 읽기만): 실제 CR 의 필드 이름과 값. 연결 카드의 "데이터" 칸에 쓴다. 설명서에 실제 값을 쓰면 작업 디렉터리의 `fixtures/<주제>/<클러스터>/expected.md` 에 값·읽는 곳·쓰는 칸을 표로 남긴다. 페이지 본문에는 날짜를 쓰지 않고 "개발 클러스터에서 읽은 값" 이라고만 적는다. 날짜는 맨 아래 "고친 기록" 에 한 줄씩 남긴다. 클러스터는 읽기만 한다.
4. **aipub-web 코드**: 화면 이름, 라우트, 문안(`src/locales/ko/**`), 판정 함수 이름. 화면 흉내의 글자는 문안 YAML 값을 그대로 쓴다.
5. 문서끼리 다르면 지어내지 않는다. 페이지에 적지 않고 작업자에게 "정책서는 A, 코드는 B" 로 보고한다.

## 규칙

- 그림이 먼저, 글은 짧게. 한 칸의 본문은 두세 문장이다.
- 2층 화면 흉내는 실제 화면의 요소 이름·문구·순서를 따른다. 값은 예시면 예시라고 적는다.
- 장면 하나는 3~6단계, 단계마다 캡션 한 문장. 커서는 실제 사용자가 누르는 곳만 누른다.
- 화면이 없는 개념(예: 설치값)은 장면에서 "화면에 바꾸는 스위치는 없다" 고 밝힌다.
- 한국어 글은 사용자 전역 규칙(조사·어미 생략 금지, 엠대시 금지, 번역투 금지)을 따른다.
- 테마 토큰·다크 모드·폰 너비는 `explainer.css` 가 맡는다. 새 색을 쓰면 토큰으로 더한다. 화면 흉내 색은 aipub-web `globals.css` 값을 따른다.
- 역할은 캐릭터로 그린다(인프라 담당자·관리자·프로젝트 매니저·프로젝트 디벨로퍼·시스템 로봇). 프로그램은 사람으로 그리지 않는다.
- 본문에 메타 설명과 날짜를 쓰지 않는다. 프론트엔드 용어(플레이그라운드 등)와 코드 경로는 독자용 본문·출처에 넣지 않는다(2층 연결 카드의 데이터 칸은 예외).

## 순서

1. 재료를 읽고 비유 하나와 칸 목록(8~12칸)을 정한다. 칸마다 2층 화면·기능·데이터를 한 줄로 적어 본다.
   - 작업 디렉터리에 그 주제의 `fixtures/` 가 있으면 먼저 Polaris 로 `expected.md` 의 값을 다시 읽어 비교한다(읽기만). 같으면 그대로 쓴다. 같아도 "고친 기록" 에 "값 다시 확인" 한 줄을 더한다. 다르면 설명서와 `expected.md` 를 새 값으로 고치고, 무엇이 바뀌었는지 "고친 기록" 에 한 줄로 적는다. 리소스가 지워졌으면 지금 있는 다른 리소스로 바꾸고 사용자에게 알린다. 클러스터를 바꾸는 명령은 쓰지 않는다.
2. 예시를 복사해 1층 칸부터 채운다. 그다음 2층 블록과 `#scenes` JSON 을 채운다(문법은 blocks.md).
3. 브라우저로 연다: 라이트·다크, 폰 너비, 모달 두세 개(자동 재생·직접 눌러 보기·대화상자 단계). 콘솔 오류와 가로 넘침이 없어야 한다. 로컬 확인은 파일 맨 위에 charset·viewport meta 를 넣고 `python3 -m http.server` 로 연다.
4. Artifact 로 올리고 링크를 준다. "읽은 것 / 못 읽은 것" 과 문서끼리 다른 곳은 페이지가 아니라 보고에 쓴다.
